# Telegram Auto Poster Bot

Телеграм-бот для отложенного и автоматического постинга в канал.
Админы присылают контент боту — бот кладёт его в очередь и публикует в заданное время с заданным интервалом. Есть статистика, роли админов и поддержка именных ботов.

---

## Возможности

* 📥 Приём сообщений (фото / видео / файлы) от админов
* ⏳ Очередь постов (SQLite)
* ⏰ Автопостинг по времени и интервалу
* 🎯 Рандомный выбор админа для публикации
* 🤖 Поддержка **именных ботов** для разных админов
* 📊 Статистика: опубликовано, в очереди, просмотры, реакции
* 🔁 Автосброс статистики по расписанию
* 🛠 Управление через команды Telegram

## Переменные окружения (`.env`)

**Звёздочкой * выделены те переменные, которые необходимо вставить напрямую в .env перед введением бота в эксплуатацию**

```env
*BOT_TOKEN=12345:qwerty          # токен основного бота
*CORE_API_ID=12341234            # api_id Telegram (telethon) — необходимо для сбора статистики админов 
                                 # и постов
*CORE_API_HASH=abcdef123456      # api_hash Telegram — необходимо для сбора статистики админов и постов
*ADMIN_UNS=ivan,petya,egor       # админы (username без @) — первая позиция - генеральный админ с доступом
                                 # ко всем командам
*CHANNEL_ID=-12345               # ID канала для постинга

BOT_MAPPINGS=                  # <bot_token>:<username>,... — заполняется через команду /addbot

# время начала и конца сессии можно установить через команду /settime
START_HOUR=0
START_MINUTE=0
END_HOUR=23
END_MINUTE=59

POSTING_INTERVAL=60             # интервал постинга (сек) можно установить через команду /setinterval
LAST_TIME_POST=2025-10-10T00:00:00 # не трогаем, изменяется автоматически
LAST_RESET_DATE=2025-11-17      # не трогаем, изменяется автоматически
RESET_INTERVAL_DAYS=7           # интервал сброса статистики можно установить через команду /resetstattime
```

### BOT_MAPPINGS

Позволяет публиковать посты **от имени разных ботов**:

```env
BOT_MAPPINGS=111:ivan,222:petya
```

Если у админа нет именного бота — используется основной.

## Запуск

### Локально

```bash
python bot.py
```

### Docker

```bash
docker compose up -d --build
```

> **Важно перед первым запуском в Docker:**
> Telethon требует интерактивной авторизации при первом запуске (номер телефона + код из Telegram).
> Docker-контейнер не поддерживает интерактивный ввод, поэтому нужно:
>
> 1. Запустить бота **локально** один раз: `python bot.py`
> 2. Пройти авторизацию Telethon (введи номер телефона и код)
> 3. Убедиться что появились файлы `*.session` в папке проекта
> 4. Только после этого запускать `docker compose up -d --build`
>
> При переносе на новый сервер — скопируй `.session` файлы вместе с `.env`.

**Убить зависший контейнер:**

```bash
bash scripts/remove_stuck_container.sh
# или с явным ID:
bash scripts/remove_stuck_container.sh abc123
```

## Команды бота

### Общие (админы)

* `/help` — список команд
* `/messages` — сохранённые сообщения

### Главный админ

* `/post <id>` — принудительно выложить пост
* `/settime HH:MM HH:MM` — время постинга
* `/setinterval <sec>` — интервал постинга
* `/resetstattime <days>` — интервал сброса статистики
* `/stat` — статистика админов
* `/config` — текущая конфигурация
* `/clear` — очистить очередь полностью
* `/clearposted` — удалить из базы опубликованные посты (например, при смене канала)
* `/collectstats` — принудительно запустить сбор статистики (просмотры, реакции)
* `/tzset` — установить часовой пояс относительно UTC

### Админы

* `/addadm @user` — добавить админа
* `/deladm @user` — удалить админа

### Боты

* `/addbot <BOT_TOKEN> @user` — добавить **именного бота** для админа
* `/deletebot @user` — удалить **именного бота**

## Как это работает

1. Админ присылает сообщение боту
2. Сообщение сохраняется в `messages.db`
3. Планировщик (`periodic_post`) проверяет:

   * время
   * интервал
   * наличие постов
4. Выбирается случайный админ
5. Пост публикуется от его именного бота (если есть)
6. Обновляется статистика и счётчики

---

## Хранение данных

* **messages.db** — очередь постов, просмотры, реакции
* **statistics.db** — статистика админов

Обе БД создаются автоматически.

## Примечания

* Бот рассчитан на **частные админ-чаты**
* Бот имеет двухуровневую систему прав: ген.админ и админы; ген.админ - первая позиция в .env/ADMIN_UNS
* Пользователь без прав не может сохранять посты
* Все изменения конфигурации пишутся прямо в `.env`

## Наглядный пример введения бота в эксплуатацию

* Без использования именных ботов

    - Заполнение необходимых (*) переменных в .env
    - Добавление бота в целевой канал (в который и будет производиться публикация сообщений)
    - Настройка оставшихся переменных - временные интервалы, дополнительные админы - через команды бота
    - Админы могут присылать сообщения либо в лс боту, либо в какую-нибудь группу с ботом
    - Эксплуатируем по полной!!
* С использованием именных ботов - нужны для подписей к постам админов

    - Передумываем эксплуатировать. Сначала создаём именных ботов и называем их именами админов.
    - Добавляем именных админов в беседу:
        * Можно добавить всех админов и именных ботов в одну беседу и осуществлять "сброс" постов туда.
        * Можно создать отдельные беседы для каждого из админов. Участниками такой беседы будут:
            * Основной бот
            * Именной бот
            * Админ
    - Связываем админов с их именными ботами через /addbot
    - Все радуются, что можно эксплуатировать программу по полной и несомненно делают это!!

* **Очень важно - иначе ничего не будет работать:**
* **При добавлении ботов выдавать им админки с правом на _назначение админов_ (Add new admins)**
